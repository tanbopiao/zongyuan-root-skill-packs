# 路由表 · federal-memory-hash-sync

| 场景/触发词 | 意图 | 路由动作 |
| --- | --- | --- |
| "推一份快照过去" / "同步到云端" | push | 运行 `sync_chain.py`：打包→链式哈希→写入→复核→留痕 |
| "查最近同步状态" | status | 读 `sync_state.jsonl` 末条：上次同步时间、chain_hash、方向、是否幂等跳过 |
| "校验链完整性" | verify_chain | 逐条重算 chain_hash，断链即报出断点行号 |
| "回读刚才那条" | readback | GET /memory/query 按 key 回读，与本地字节比对 |
| "内容没变还要推吗" | idempotent_q | 答：不变即跳过（SYNC_UNCHANGED），这是设计而非故障 |
| "断链了怎么办" | broken_chain | 停写、报警、人工仲裁哪端为真后重起链（GENESIS 或对齐基线） |

## 宿主集成约定

- 定时任务建议每小时一班；绿轮静默，红轮（写入失败/复核不一致/断链）才报警；
- 网关不可达时指数退避重试（建议 1/2/4 分钟三档），连续失败挂起并留痕；
- 快照打包失败不阻塞主业务，只留 `ERROR` 级留痕。

## 例外与边界

- 令牌文件丢失 → 视为无写权，只读通道照常；补令牌走安全授权入口，不进对话；
- 两端哈希冲突（同 key 不同 payload）→ 人工仲裁优先级，不在自动同步里静默覆盖；
- 本技能不做加密：需要机密级同步请在 payload 层自行加密后再入链。
