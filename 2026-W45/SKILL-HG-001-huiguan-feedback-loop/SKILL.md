# 规约回灌闭环

> 分层规约装配 → 逐字校验 → 逃逸负例回灌 → 重生成复判 → 正例回灌 → 指标留痕。
> 一套可落地的「质量自愈」骨架，源自 ZONGYUAN-ROOT 规约回灌中枢 V0.2 的实战提炼。

## 一、解决什么问题

LLM/智能体在长会话中会「漂移」：说了不该说的（泄密、越权、口径走样），或漏说了必须说的（关键留痕、确认步骤）。事后靠人肉审句既贵又不稳定。

本技能把质量治理做成**机器可执行的闭环**：

1. 用「分层规约」替代散落的提示词规则；
2. 输出用「P0 校验器」逐字把关；
3. 违规输出被自动打成**负例**回灌进样例池；
4. 自动**重生成**（限次），复判通过后把合格输出存为**正例**；
5. 全程留痕，跑出可复盘的逃逸率指标。

## 二、核心闭环（七步）

```
1. 装配 assemble   : 按意图/场景从规约库取出活跃规约，组装为执行包 pack
2. 执行 execute    : 把任务交给可插拔的执行器（LLM/流水线/脚本均可）
3. 校验 verify     : P0 正则 + 规约逐字核验，输出判定
4. 负例回灌        : 校验不过 → 违规输出入负例池，并定位违了哪条规约
5. 重生成 regenerate: 携带「负例+违规点」重新生成，重试上限默认 2 次
6. 复判 re-verify  : 重生成输出再过同一校验器，通过则收
7. 正例回灌        : 合格输出入正例池（附置信度），下次装配时作为 few-shot 参考
```

重试用尽仍不达标 → **升级人工复核**，并留下完整轨迹（不许静默丢弃）。

## 四、快速开始

1. 把 `templates/` 三个文件拷进你的项目；
2. 在 `verify_skeleton.py` 中按你自己的 P0 规则改写 `P0_RULES`（参考内置的秘钥泄漏类正则，换成你的业务红线）；
3. 实现/替换 `default_executor`，接上你的生成器；
4. 跑 `run_session("demo-001", task_output, scene="*", intent="...")` 看闭环日志；
5. 正负例池随真实运行持续生长，`metrics()` 查看 7 日逃逸率。

## 五、关键约定

- **层1 规约不参与装配路由**：全局宪法层规约恒在背景，不因场景注入路由而缺失；
- **缺字段视为存活**：规约缺 `status` 字段时按 `ACTIVE` 处理，避免静默失效；
- **样例正文不外发**：同步/上报时只带摘要与哈希，正文留在本地，防污染真值池；
- **台账只增不覆盖**：`ledger.jsonl` 追加写，出问题靠版本链回溯，不删历史；
- **重试上限硬编码可见**：默认 ≤2 次，用尽必升级，不无限重试掩盖问题。

## 六、指标口径

| 指标 | 含义 |
| --- | --- |
| escape_rate_7d | 近 7 日首检逃逸率 = 首检未过的会话数 / 总会话数 |
| lora_review_needed | 待人工复核的「重试用尽」会话数 |
| positive/negative | 正/负例池存量（样例摘要计数） |

## 七、适配场景

- 智能体输出合规把关（秘钥/个人信息/越权话术）；
- 生成式流水线的风格与口径稳定性治理；
- 多智能体协作中「下游校验上游」的通用回路；
- 任何「规则库 + 执行器 + 校验器」三件套可表达的治理问题。
