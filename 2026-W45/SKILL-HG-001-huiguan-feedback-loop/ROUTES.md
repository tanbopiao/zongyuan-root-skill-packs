# 路由表 · huiguan-feedback-loop

本表定义「什么场景应该路由到本技能」。宿主 Agent / 调度器可按左列匹配触发词或场景标签，进入对应动作。

| 场景/触发词 | 意图 | 路由动作 |
| --- | --- | --- |
| "输出合规校验" / "把输出过一遍红线" | verify | 调用 `verify()`：对给定输出跑 P0 规约 + 逐字核验，返回判定与违规点 |
| "装配本次执行的规约包" | assemble | 调用 `assemble_pack(intent, scene)`：按意图与场景取活跃规约，返回 pack 与路由清单 |
| "这条输出违规了，记下来" | feedback_escape | 调用 `feedback_escape()`：写入负例池并关联违规规约 |
| "这条输出很好，存作范例" | feedback_positive | 调用 `feedback_positive()`：写入正例池（带置信度） |
| "重生成一次，把违规点带上" | regenerate | 调用 `regenerate()`：携带负例与违规点重生成，计数重试上限 |
| "查最近七天逃逸率" / "质量指标" | metrics | 调用 `metrics()`：返回 escape_rate_7d / lora_review_needed / 池存量 |
| "升级人工复核" | escalate | 重试用尽后的既定动作：完整轨迹入待复核队列，不静默丢弃 |

## 装配分层约定

- `layer >= 2` 的规约按 `scene` 过滤后参与装配（`*` 通配全场景）；
- `layer == 1`（宪法层）恒在背景生效，**不**进路由装配结果，装配输出中不携带、但校验时必须覆盖；
- 缺 `status` 字段按 `ACTIVE` 处理。

## 例外与边界

- 样例正文（正/负例池中的具体文本）仅本地使用；对外同步时只发摘要与哈希；
- `P0_RULES` 属安全红线，任何场景不得绕过校验器直接放行；
- 台账与轨迹只增不覆盖，修复问题时写新记录、不改旧记录。
