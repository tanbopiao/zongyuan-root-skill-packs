# 方法论 · 规约回灌闭环 V0.2 提炼

来源：ZONGYUAN-ROOT 规约回灌中枢（DID-BR-000002），2026-11-02 完成逃逸重生成闭环与联邦同步实跑后的通用化提炼。

## 1. 为什么分层

单一提示词规则列表有三个致命伤：不可路由（所有场景背全部规则）、不可升级（改一条全量重测）、不可度量（说不出哪条规约在起作用）。分层后：

| 层 | 角色 | 特性 |
| --- | --- | --- |
| 1 宪法层 | 全局红线与身份锚点 | 恒在背景，不参与路由；任何装配不得遗漏其约束 |
| 2 场景层 | connect/deploy/push 等场景规约 | 按 scene 过滤装配，版本可演进 |
| 3 红线层 | P0 正则级硬约束 | 校验器直接实现，机器可判，零解释空间 |

## 2. 闭环的四个反馈点

1. **首检逃逸**：verify 不过 → 负例回灌（记 rule_id 与命中片段，片段截断防二次泄漏）；
2. **重生成**：把负例+违规点注入执行器上下文再生成；上限 2 次——超过说明规约或执行器有系统性问题，不是多试几次能解决的；
3. **复判通过**：正例回灌，置信度随重试次数递减（1/(1+attempts)），让"一次过"的样本权重最高；
4. **升级**：用尽上限 → 完整轨迹（装配包、每轮输出、判定）入待复核队列。人只处理机器解决不了的尾部。

## 3. 实战教训（提炼自 V0.2 运行）

- **核解析 bug 与重试用尽留痕 bug 都在真实运行中暴露**：闭环不跑起来就永远发现不了自己的漏洞，先跑通最小环再谈完备；
- **规约库并发覆写**：多进程并行写同一规约库会产生互相覆盖，需文件锁或单写者队列；被覆盖的宪法层规约要及时恢复并留痕；
- **样例池要先"瘦身"再通用**：正文含内部路径/令牌的样例绝不能进公开同步流，同步协议层面只传摘要+哈希；
- **逃逸率是治理北极星**：escape_rate_7d 连续走低说明规约在起作用；不降反升通常意味着执行器换了但规约没跟上。

## 4. 与联邦同步的关系

规约库与样例池是本地热数据；跨环境复制时走哈希链同步（见 SKILL-FM-001），保证两端账本可校验、可合并、不冲突。两包组合使用效果最佳。
