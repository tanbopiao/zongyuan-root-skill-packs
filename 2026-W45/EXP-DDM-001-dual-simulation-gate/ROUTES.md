# 路由表 · dual-simulation-gate

| 场景/触发词 | 意图 | 路由动作 |
| --- | --- | --- |
| "这个能不能直接推/直接改" | gate_check | 读取事项背景 → 开双轮推演 → 产出台账 |
| "远端推送 / 对外发布 / 花钱 / 删除" | high_risk | 强制走双推演门；台账缺两轮不得执行 |
| "两轮结论冲突了" | conflict | 升级人工拍板，把两轮分歧点并排呈现 |
| "事项超出判据覆盖" | out_of_scope | 同上：宁可多问，不擅自扩权 |
| "推演通过，开干" | proceed | 按台账执行窗推进，逐条附条件核验后放行 |
| "事后复核" | post_audit | 执行后回填台账：实际结果 vs 推演预测，偏差即固化教训 |

## 何时不必过门

- 纯只读操作（查询、巡检、探活）；
- 六判据全为既有事实的例行事项（如已授权的每日定时任务按既定指令执行）；
- 用户/上级当场明确发令的一次性动作（执行前仍应把关键风险口头复述一句）。

## 例外与边界

- 判据是「门」不是「枷锁」：只适用于改动类高风险动作，不用于拖延常规工作；
- 两轮推演必须独立：第二轮不得看见第一轮的结论再「顺着他写」；
- 台账是唯一权威凭证：没有台账的自主推进视为未过门。
