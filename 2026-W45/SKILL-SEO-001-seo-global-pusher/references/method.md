# 方法论 · SEO 全域推送

## 1. 差分推送为什么是关键

全量推送每个站点动辄数百 URL，重复推送会稀释引擎侧配额（尤其百度有每日配额），也让 IndexNow 触发引擎侧反作弊。以 sitemap 的 `lastmod` 为变更判据：URL 不在 state → 新增；lastmod 变了 → 变更。其余静默跳过。

## 2. 双通道分工

| 通道 | 覆盖 | 特点 |
| --- | --- | --- |
| IndexNow（api.indexnow.org 单口） | Bing / Yandex / Naver / Seznam | 无配额焦虑，host+key 验证即可，秒级生效 |
| 百度链接提交 API | 百度 | 有每日配额，token 从搜索资源平台获取；无 token 自动跳过，不阻塞主链 |

## 3. 密钥与安全

- IndexNow key = 32 位 hex，key 文件必须可公开访问（引擎会抓取验证站点所有权）；
- key 与百度 token 属站点凭据：入配置文件（权限 600），不进代码、不进日志、不进台账正文。

## 4. 实战经验（提炼自 346 条全绿推送）

- **每次推送落 ledger**：推送出问题（如引擎返回 4xx）时，时间线回放比记忆可靠；
- **state 更新用原子替换**（tmp → os.replace），避免中途崩溃导致状态半写；
- **批量上限 1000/次**：IndexNow 单请求 URL 列表建议不超过 10000，分批更稳；
- **差分推送配合内容日更**：固定一个低峰时段（如每日 10:20）跑一班，绿轮静默；
- **新站冷启动用 --full 打基线**，之后严禁全量重推。

## 5. 验证闭环

推送只是第一步，收录是第二步。验证方式：`site:你的域名 关键词` 抽查快照时效；或在搜索引擎后台（Bing Webmaster / 百度资源平台）看提交反馈。不要用第三方"收录查询"接口替代官方通道。
